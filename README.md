# МиниСклад — учебная конфигурация 1С

Учебный проект курса 1С-разработки (kb99). В корне репозитория — выгрузка конфигурации «МиниСклад» в XML, актуальная на последнюю неделю обучения. История развития — в коммитах по неделям.

Автор: Алампиева Алена.

## История по неделям

| Неделя | Что добавлено |

| 1 | Справочники (Номенклатура, Контрагенты, Склады, Сотрудники), документы Поступление и Реализация, подсистемы |
| 2 | Регистры накопления (ОстаткиНоменклатуры, ПартииНоменклатуры, Продажи), проведение документов |
| 3 | 7 отчетов на СКД (ОборотыПоТоварам, ОстаткиНаДату, Материалы, ВыручкаИСебестоимость, РеестрДокументовРеализация, РейтингУслуг/Клиентов, ВыручкаМастеров, Универсальный), печатная форма, списание по FIFO |

## Как развернуть с нуля

Нужна платформа 1С:Предприятие 8.3.27 или новее (подойдет комьюнити-версия для разработчиков с developer.1c.ru).

1. Скачать репозиторий: зеленая кнопка **Code → Download ZIP** — и распаковать в короткий путь, например `C:\tmp\ms` (путь не должен быть глубоким).
2. В окне запуска 1С нажать **Добавить** → «Создание новой информационной базы» → «Создание информационной базы без конфигурации…» → указать каталог базы.
3. Открыть базу в режиме **Конфигуратор**.
4. Меню **Конфигурация → Загрузить конфигурацию из файлов…** → указать распакованную папку (где лежит `Configuration.xml`) → «Загрузить».
5. На вопрос об обновлении конфигурации базы данных ответить **Да** (или нажать **F7**), в окне реорганизации информации — **Принять**.
6. С недели 5 в базе нужен пользователь: **Администрирование → Пользователи** → добавить пользователя с ролью «Администратор» (без пользователей база открывается с полными правами, но роли не проверить).
7. Запустить **1С:Предприятие** (F5). Данные (номенклатуру, цены в регистре «Цены» и т.п.) ввести вручную — в выгрузке только структура конфигурации, без данных.

Нужна версия на конец конкретной недели — открой историю коммитов (Commits), выбери коммит нужной недели и скачай ZIP оттуда (Browse files → Code → Download ZIP).

## Что нового в неделе 4

- **Подбор товаров** в документах Поступление и Реализация: форма выбора Номенклатуры с множественным выбором, повторный выбор увеличивает количество строки (+1), сумма пересчитывается.
- **Условное оформление** списка Номенклатуры: услуги выделяются цветом, группы — жирным (настройки динамического списка формы списка).
- **Проверка заполнения** в Реализации (`ОбработкаПроверкиЗаполнения`): «Мастер» обязателен только при наличии услуг в документе; запрет выбора группы в табличной части с привязкой сообщения к полю строки.

## Что нового в неделе 5

- **Роли** (`Roles`): Администратор (все права, «Устанавливать права для новых объектов»), Кладовщик (Поступление, остатки и партии, складские отчёты; Реализация недоступна), Менеджер (Реализация, контрагенты, продажи), Бухгалтер (просмотр всех справочников, документов, регистров и отчётов без изменения).
- **Регламентное задание** `КонтрольОстатков` (`ScheduledJobs`) + общий модуль `РегламентныеЗаданияСервер`: по расписанию проверяет остатки товаров (без услуг и групп) и пишет в журнал регистрации предупреждение по товарам с остатком меньше 2 и итоговую запись. В файловой базе задание выполняется, пока открыт сеанс 1С:Предприятия.
- **Внешняя печатная форма** «Акт о списании товаров (кв99)» для УТ 11 — папка [`ВнешняяПечатнаяФорма`](ВнешняяПечатнаяФорма/README.md) (обработка в XML и инструкция по подключению).

## Что нового в неделе 6

Неделя учитывает замечания наставника по неделе 4 и автопроверки по неделе 5: обращения «через точку» в циклах заменены одним запросом.

- **RLS по складу.** Параметр сеанса `ТекущийСклад` заполняется в модуле сеанса из нового регистра сведений `СкладыПользователей` (Пользователь → Склад). В ролях Кладовщик (Поступление) и Менеджер (Реализация) на чтение, добавление и изменение стоит ограничение `#ПоСкладу("Склад")` по шаблону `ПоСкладу(ИмяПоля)`. Новые документы сами подставляют склад пользователя (`ОбработкаЗаполнения`).
- **Роль Гость:** только просмотр справочников, документов, регистров и отчетов.
- **Справочник «Товары к дозаказу».** Регламентное задание `КонтрольОстатков` за один пакетный запрос находит товары с остатком меньше 2. В одной транзакции оно добавляет и обновляет их в справочнике, лишние удаляет, итог пишет в журнал регистрации.
- **Оптимизация кода:**
  - проверка заполнения Реализации получает признаки «группа / услуга» одним запросом (`В ИЕРАРХИИ`);
  - подбор получает цены одним запросом к `Цены.СрезПоследних` (`РаботаСоСправочниками.РозничныеЦены`);
  - внешняя печатная форма получает товары одним запросом с `ПРЕДСТАВЛЕНИЕ()`.
- **HTTP-сервис `ОбменJSON`** (корневой URL `exchange`):
  - `GET /hs/exchange/stock` (необязательный параметр `?warehouse=Имя склада`) — остатки с ценами в JSON;
  - `POST /hs/exchange/receipt` — принимает JSON `{"warehouse": "Основной", "comment": "...", "items": [{"code": "...", "quantity": 1, "price": 10}]}`, создает и проводит Поступление. Ответ `201` с номером документа или `400` со списком ошибок.
- **Имитация внешней системы** — папка `ИмитацияВнешнейСистемы`. Запустить `ЗапуститьИмитацию.bat`: скрипт PowerShell выполнит GET остатков, POST поступления и POST с ошибкой.

### Настройка после загрузки (неделя 6)

1. **Склады пользователей:** в регистре сведений «Склады пользователей» указать имя пользователя ИБ и его склад. Если записи нет, ограничение RLS не даст пользователю с ролью Кладовщик или Менеджер увидеть документы.
2. **Регламентное задание** в файловой базе выполняется, только пока открыт сеанс 1С:Предприятия.
3. **Публикация HTTP-сервиса на IIS (Windows):**
   - включить компоненты Windows «Службы IIS» + «Расширения ISAPI»;
   - при установке платформы 1С отметить компонент «Модули расширения веб-сервера»;
   - запустить Конфигуратор **от имени администратора** → Администрирование → Публикация на веб-сервере → имя `minisklad`, флажок «Публиковать HTTP-сервисы» → Опубликовать;
   - дать пользователям `IUSR` и `IIS_IUSRS` право «Изменение» на каталог базы;
   - если платформа 32-разрядная: в диспетчере IIS → Пулы приложений → DefaultAppPool → Дополнительные параметры → «Разрешены 32-разрядные приложения» = True (иначе ошибка 500, код 0x800700c1);
   - проверить в браузере: `http://localhost/minisklad/hs/exchange/stock` (базовая авторизация, пользователь ИБ).
